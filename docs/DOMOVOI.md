# DOMOVOI

Анализатор диска для macOS в духе DaisyDisk: показывает, где лежит занятое место, рекомендует, что можно убрать, и отвечает на вопросы о диске с помощью локальной языковой модели. Написан на Rust, диаграмма рисуется в Metal.

Имя: Домовой — хранитель дома из славянской мифологии, который знает каждый угол и держит порядок, но ничего не делает без спроса.

Визуальная спецификация: `design/domovoi-design-book.html` (дизайн-книга, разделы I–XI). Этот документ описывает продукт и архитектуру. Книга описывает внешний вид, компоненты, экраны и правила рендера. При расхождении в визуальных вопросах права книга, в остальных — этот документ.

---

## 1. Принципы

1. **Честные числа.** Показываем только измеренное: размер на диске (allocated), а не логический. Hard links считаются один раз. Клоны APFS помечены. Скрытое место (purgeable, снапшоты, системные данные) показано отдельно и не смешивается с файлами.
2. **Правила решают, модель объясняет.** Безопасность удаления определяет только детерминированный движок правил. Модель классифицирует незнакомое и отвечает на вопросы. Её выводы всегда помечены как гипотеза и попадают в категорию «Проверьте сами».
3. **Ничего без спроса.** Удаление только после подтверждения и только того, что отмечено к удалению; удаление необратимо. Системные пути, SIP-защищённые области и активные бандлы приложений закрыты denylist.
4. **Ничего наружу.** Модель видит только метаданные. Процесс инференса не имеет доступа к сети.
5. **Приложение работает без модели.** Скан, диаграмма, правила, дубликаты и очистка доступны сразу. AI включается отдельно.
6. **Модель тоже занимает место.** Скачанная модель видна на диаграмме отдельной категорией и удаляется в один клик.

## 2. Принятые решения

| # | Область | Решение |
|---|---|---|
| 1 | Объём сканирования | Только системный том. Другие тома, внешние и сетевые диски не сканируются. |
| 2 | Сканер | `getattrlistbulk`, параллельный обход по поддеревьям, allocated size, кэш скана на диске, инкрементальные обновления через FSEvents. При выходе окно закрывается сразу, а кэш дописывается в фоне: приложение отвечает `NSTerminateLater` и завершается, когда запись готова. Идентичность файлов: инод — `(ATTR_CMNEXT_REALDEVID, ATTR_CMN_FILEID)`, поток данных (клоны) — `(ATTR_CMNEXT_REALDEVID, ATTR_CMNEXT_CLONEID)`, запись каталога — `ATTR_CMNEXT_LINKID`. `st_dev` ключом не служит: у системного и Data-тома он одинаков. |
| 3 | Дубликаты | Отдельная опция и отдельный проход: группировка по размеру → частичный хэш → полный BLAKE3. Клоны APFS распознаются. |
| 4 | Рекомендации | Детерминированный движок правил с уровнями безопасности. Модель не принимает решений об удалении. |
| 5 | Удаление | Собственный движок: элемент удаляется обходом в глубину на дескрипторах (`openat` с `O_NOFOLLOW`, `getattrlistbulk`, `unlinkat`, каталог — после содержимого), дети элемента в 4 потока, перед удалением сверка `link_id` с индексом. Точки монтирования и firmlink не обходятся, флаги и ACL не снимаются. Счёт идёт по файлам, итог — из индекса; «Остановить» срабатывает между файлами. Корзина Finder не используется. Перед действием всё собирается в список «К удалению». |
| 6 | Данные для модели | Только метаданные: путь, имя, размер, тип/UTI, даты создания и изменения, `kMDItemLastUsedDate`, принадлежность приложению. Содержимое файлов не читается. `kMDItemWhereFroms` исключён. |
| 7 | Рантайм модели | llama.cpp, статически слинкованный, на запиненном коммите. Metal-бэкенд; предкомпилированные `default.metallib` и `ggml-tensor.metallib` лежат в бандле XPC-сервиса (`GGML_METAL_EMBED_LIBRARY=OFF`: встроенный вариант хранит исходник шейдеров и компилирует его при каждой инициализации бэкенда). |
| 8 | Биндинги | Свои, тонкий слой через bindgen над `llama.h`. Готовые крейты не используются. |
| 9 | Изоляция инференса | XPC-сервис внутри бандла (`Contents/XPCServices`), протокол через C API `libxpc`. У сервиса нет сети. |
| 10 | Формат ответов модели | Structured output и tool calling через грамматику GBNF, построенную из JSON-схемы. Модель физически не может ответить вне схемы. Конвертер JSON-схема → GBNF свой, на Rust: публичный `llama.h` принимает только готовую GBNF, конвертер llama.cpp живёт в C++ `common/`. |
| 11 | Шаблоны промптов | Свои для каждого семейства моделей, хранятся в каталоге. Встроенные шаблоны llama.cpp не используются. |
| 12 | Выгрузка модели | После простоя. Таймаут выбирает пользователь: сразу, 5, 15, 60 минут, никогда. |
| 13 | Загрузка модели | Внутри приложения, своим загрузчиком: HTTP Range (докачка), пауза, отмена, проверка SHA-256, проверка свободного места. Бинарник приложения моделей не содержит. |
| 14 | Каталог моделей | Зашит в версию приложения. Новые модели приходят с релизами. Источник загрузки настраивается (зеркало или файл вручную), подлинность проверяется по SHA-256. |
| 15 | Интерфейс | AppKit через objc2: окно, сайдбар, списки, карточки, чат, настройки. Metal только для диаграммы. |
| 16 | Дистрибуция | Вне Mac App Store: Developer ID, notarization, обновления через Sparkle. |
| 17 | Единицы | Десятичные, как в Finder: 1 ГБ = 10⁹ байт. Десятичная запятая, неразрывный пробел перед единицей. |
| 18 | Платформа | Только Apple Silicon (arm64), macOS 15 и новее. Tahoe — последний релиз для Intel; классы каталога «по общей памяти» и Metal-бэкенд предполагают unified memory. |

## 3. Решения, принятые при планировании

1. **Визуализация:** оба режима с переключателем, по умолчанию sunburst. Сильные стороны не пересекаются: у солнца видна иерархия и естественный радиальный зум, у карты — честные пропорции и подписи в плитках.
2. **Действие над дубликатом:** по умолчанию копии удаляются окончательно. «Заменить клоном» — отдельное явное действие для группы: `clonefile` оригинала во временное имя рядом с копией, перенос метаданных копии, проверка непосредственно перед заменой, атомарный обмен `renameatx_np(RENAME_SWAP)`, старое тело удаляется тем же движком. Действие доступно, только когда копия одна на своём иноде, принадлежит пользователю, не открыта, не лежит в пакете или облачной папке.
3. **Состав каталога моделей:** только семейство шаблонов ChatML, все веса Apache-2.0. Компактная (8 ГБ) — Qwen3.5-4B, альтернатива Qwen3-4B-Instruct-2507; стандартная (16 ГБ) — T-lite-it-2.1, альтернатива Qwen3.5-9B; расширенная (32+ ГБ) — Qwen3-14B. Отклонены по лицензии YandexGPT-5-Lite, Gemma 1–3, Llama, xLAM, EXAONE, LFM; по семейству шаблона — Phi-4-mini, Gemma 4, Mistral. Основную модель класса подтверждает собственный русскоязычный эвал на инструментах DOMOVOI.

## 4. Подсистемы

### 4.1 Сканер

- Обход через `getattrlistbulk`: имена, тип, allocated size, inode, даты пачкой за один syscall.
- Параллельность по поддеревьям, work-stealing.
- Сторож файловой системы: активность отмечается на каждую пачку `getattrlistbulk` и на каждом витке ожидания защищённых папок; 60 с без активности (как у DaisyDisk) обрывают скан ошибкой «Файловая система не отвечает» с путём последней папки и кнопкой «Открыть Дисковую утилиту», прежний индекс остаётся. Часы монотонные и стоят во время сна, поэтому пробуждение не считается простоем.
- Data-том системного контейнера; firmlinks между `/` и `/System/Volumes/Data` учитываются, чтобы ничего не посчитать дважды.
- Примонтированные тома и точки монтирования внутри дерева пропускаются.
- Hard links считаются один раз по иноду `(ATTR_CMNEXT_REALDEVID, ATTR_CMN_FILEID)`.
- Sparse-файлы считаются по allocated size.
- Клоны APFS распознаются по потоку данных `(ATTR_CMNEXT_REALDEVID, ATTR_CMNEXT_CLONEID)` и флагу `EF_SHARES_ALL_BLOCKS`: размер получает один канонический элемент группы, остальные помечаются «клон» и «делит блоки с N». Частично разошедшиеся клоны публичным API не измеряются и считаются полностью.
- Скрытое место считается отдельно, без обхода файлов: purgeable, локальные снапшоты Time Machine, системные данные.
- **Full Disk Access.** Без него TCC закрывает `~/Library`, Mail, Safari и данные приложений. Приложение определяет отсутствие доступа, показывает экран онбординга и ведёт в Настройки; иконку приложения с этого экрана можно перетащить прямо в список Full Disk Access (`NSDraggingSource` с URL бандла), а после выдачи права экран предлагает перезапуск. Без доступа скан работает, но показывает, сколько папок скрыто.
- **Кэш.** Результат скана сохраняется на диск. Повторное открытие мгновенное, затем применяются дельты FSEvents.

### 4.2 Индекс

Дерево узлов в памяти. Узел хранит: имя, тип, allocated size (своё и суммарное), число файлов, даты, `kMDItemLastUsedDate` (если доступно), категорию, признак клона, признак hard link, принадлежность приложению (bundle id, установлено ли приложение) и доказательство этой принадлежности.

Владелец папки определяется точным признаком: папка названа bundle id, `MCMMetadataIdentifier` в метаданных контейнера, группа из entitlements `application-groups` подписи, префикс Team ID у Group Containers, задание launchd с `AssociatedBundleIdentifiers` или `Program` внутри бандла. Совпадение только по имени с установленной программой — отдельное слабое доказательство. Установленные программы индекс берёт из бандлов `.app` на всём томе (`Info.plist` и подпись через Security), затем из Spotlight и `NSWorkspace`; программа считается удалённой, только если её нет нигде. Общая группа нескольких программ одного вендора владельца не получает. Индекс, построенный на точке монтирования, видит пути относительно этого тома.

Категории: Приложения, Разработка, Медиа, Документы, Кэши, Система, Скрытое, Модель. Цвета категорий — в книге, раздел II.

Индекс отвечает на запросы с фильтрами (категория, безопасность правила, минимальный размер, давность последнего использования, префикс пути). Этими же запросами пользуется агентный цикл модели.

### 4.3 Визуализация

- `MTKView` в режиме по запросу: кадр рисуется только при изменении данных, наведении или анимации. Во время анимаций — до 120 Гц на ProMotion.
- Сегменты — инстансы: SDF-дуга (sunburst) или прямоугольник (treemap), один draw call.
- Hit-testing на CPU: полярные координаты для sunburst, дерево прямоугольников для treemap. Попадание различает узел и группу (`Hit::Node` / `Hit::Group`).
- Мелкие объекты: дуги уже 0,1 % окружности не рисуются по отдельности, а складываются в один сегмент «мелкие объекты» в конце сектора своего каталога, поэтому кольцо сходится с родителем. Группа идентифицируется родителем, а не отдельным номером узла. Клик или Enter раскрывает её на текущем уровне; пункт «Вид ▸ Всегда раскрывать мелкие объекты» раскрывает все группы. Treemap группу не использует.
- Анимации: радиальный зум 220 мс, приглушение остальных сегментов при наведении 120 мс, сжатие сегмента при отметке к удалению 320 мс. Сектор роста во время скана отражает байты обойдённых файлов к занятому месту тома: углы сегментов пропорциональны байтам, поэтому сектор идёт в такт счётчику в центре; доля обойдённых каталогов для сектора не подходит и была отменена. При `prefers-reduced-motion` переходы заменяются сменой кадра.
- Текст: растровый атлас глифов через Core Text на точный пиксельный размер экрана (с кириллицей и системным фолбэком шрифтов), раскладка и обрезка строк через `CTLine` / `CTLineCreateTruncatedLine`. SDF для текста не используется: ниже ~18 px он размыт и не хинтуется. При зуме битмап масштабируется до финального кадра, как в Core Animation.
- Текст в центре круга подгоняется по хорде на высоте строки: сначала уменьшение до минимального размера, затем многоточие.
- Подписи treemap рисуются только в плитках больше порога, иначе имя доступно по наведению.

### 4.4 Движок правил

Правило: идентификатор, набор путей или шаблонов, уровень безопасности, пояснение для пользователя.

Уровни безопасности:

- **Безопасно** — пересоздаётся само.
- **Восстановимо** — можно скачать заново, но что-то пропадёт.
- **Проверьте сами** — могут быть данные пользователя.

Стартовый набор правил:

| id | Что | Уровень |
|---|---|---|
| `xcode.derived-data` | Xcode DerivedData | Безопасно |
| `xcode.device-support` | iOS DeviceSupport | Восстановимо |
| `cargo.target` | каталоги `target/` Rust-проектов | Безопасно |
| `dev.deps` | `node_modules`, `zig-cache` и подобные | Безопасно |
| `dev.python` | `.venv`, `__pycache__`, `.mypy_cache`, `.pytest_cache` Python-проектов | Безопасно |
| `dev.web-build` | `.next`, `.nuxt`, `.turbo` | Безопасно |
| `dev.cocoapods` | `Pods` проектов CocoaPods | Безопасно |
| `dev.swiftpm` | `.build` пакетов Swift | Безопасно |
| `caches.user` | `~/Library/Caches` | Безопасно |
| `downloads.installers` | `.dmg` и `.pkg` в Загрузках | Восстановимо |
| `xcode.simulators` | симуляторы CoreSimulator | Проверьте сами |

Уровни трёх правил уточнены разведкой. DeviceSupport — Восстановимо: символы вернутся только при следующем подключении устройства. Установщики — Восстановимо: их придётся скачать заново, если программа понадобится снова. Симуляторы — Проверьте сами: внутри живут установленные приложения и их данные; отдельное подправило для симуляторов удалённых версий ОС остаётся «Безопасно».

Проекты разработки. Находки правил с шаблоном «папка рядом с маркером» (`target` рядом с `Cargo.toml`, `node_modules` рядом с `package.json`, `.next`, `.venv`, `Pods`, `.build` и подобные) собираются не в карточки своих правил, а в одну карточку «Проекты разработки». Строка карточки — проект: ближайшая папка с `.git` над артефактом, если это не домашняя папка и не корень тома, иначе папка с маркером; пакеты монорепо с `.git` — одна строка. В строке — имя и путь проекта, найденные артефакты, давность последнего изменения файлов проекта (без артефактов и `.git`) и размер. Проекты без изменений больше месяца стоят первыми; отмечают строку, группу или всю карточку. Проект, который ничего не освобождает (0 Б), не отмечается ни строкой, ни группой, ни карточкой, а карточка считается отмеченной целиком, когда отмечены все остальные проекты. Отмеченные проекты уходят в «К удалению» строкой на проект. Общий `target-dir` из `~/.cargo/config.toml` проекту не принадлежит и остаётся в карточке «Каталоги target/ (Rust)». Артефакт внутри пакета (`.app` и подобных), внутри чужих зависимостей (папки пакета в `node_modules`, глобальные npm, nvm) и в каталогах инструментов (расширения VS Code и подобных редакторов, глобальные pnpm и bun) проектом не считается: это часть установленной программы, и в рекомендации он не попадает.

Клоны в каталогах зависимостей массовы: менеджеры вроде pnpm и bun кладут файлы в проекты клонами из общего хранилища. Поэтому выигрыш правил считается не по allocated size, а по `reclaimable` — сколько места освободится на самом деле: для сжатых файлов это allocated size, если файл ни с кем не делит блоки, для остальных — `ATTR_CMNEXT_PRIVATESIZE`, перечитанный в момент показа.
| `docker.vm` | диск виртуальной машины Docker | Проверьте сами |
| `ios.backups` | резервные копии iPhone и iPad | Проверьте сами |
| `xcode.archives` | архивы Xcode | Проверьте сами |
| `apps.leftover-caches` | кэши, сохранённые окна и данные WebKit удалённых программ | Безопасно |
| `apps.leftover-data` | контейнеры, данные, группы, настройки и задания launchd удалённых программ | Проверьте сами |
| `logs.crash-reports` | отчёты о сбоях в `~/Library/Logs/DiagnosticReports` и `/Library/Logs/DiagnosticReports` | Восстановимо |
| `logs.user` | журналы программ в `~/Library/Logs` | Безопасно |
| `mail.downloads` | копии вложений, открытых из Почты | Восстановимо |
| `trash.user` | содержимое Корзины Finder | Проверьте сами |
| `screenshots` | снимки экрана на Рабочем столе, в Документах, Загрузках, Изображениях и в папке снимков | Проверьте сами |

Снимок экрана — файл, который Spotlight помечает `kMDItemIsScreenCapture`; имя файла признаком не считается. Правила журналов, вложений и Корзины забирают содержимое системных папок, сами папки остаются на месте. Отчёты о сбоях — Восстановимо: по ним разбирают повторяющиеся сбои. Корзина — Проверьте сами: из очищенной Корзины файл не вернуть.

Остаток — папка, владелец которой назван точным признаком, а самой программы нет ни среди бандлов индекса, ни в Spotlight, ни в `NSWorkspace`. Правило остатка забирает такую папку целиком: внутри неё ничего не нужно установленным программам. Совпадение только по имени остатком не бывает. Установка или удаление программы при открытом Домовом сразу пересчитывает остатки: данные поставленной заново программы уходят из них, данные удалённой появляются.

Правила для кэшей пакетных менеджеров (Homebrew, npm, cargo, pip, Yarn, SwiftPM) входят в `caches.user` или выделяются отдельно — решает планирование.

- **Denylist** закрывает системные пути, SIP-защищённые области и бандлы запущенных приложений. Ни правило, ни пользователь не могут отметить их к удалению. Единственное исключение внутри защищённых данных — `Mail Downloads` в контейнере Почты: его содержимое забирает `mail.downloads`, остальная Почта закрыта. Корзина Finder открыта для `trash.user`; `.Trashes` томов и Корзина iCloud (`~/Library/Mobile Documents/.Trash`) закрыты.
- **К удалению** — список сбора перед действием. Показывает итог; после подтверждения удаляет всё окончательно одной операцией с полосой и счётом файлов («Удаляю: N из M файлов»), которые движутся и внутри одной огромной папки, с кнопкой «Остановить» и отчётом: удалено и освобождено, не удалено с причиной. Пока удаление не началось, у каждой строки листа есть крестик «Снять отметку»: строка уходит из списка целиком — отдельная папка, все пути одного правила, проект со всеми его артефактами или программа со всеми её файлами, — и лист пересчитывает итог заново. Пустой лист подсказывает, откуда берутся отметки: перетащить строки списка на кнопку «К удалению», отметить рекомендации или копии дубликатов.

### 4.5 Дубликаты

- Запускается вручную, отдельным проходом с прогрессом и отменой.
- Конвейер: группировка по размеру → хэш первых и последних блоков → полный BLAKE3 для оставшихся кандидатов любого размера. Отмена и лимит облачного прохода срабатывают и посреди чтения файла.
- Оставляемым становится экземпляр внутри пакета (`.app`, библиотеки программ), затем вне Корзины, затем вне хранилищ зависимостей, затем самый старый. Копию внутри пакета отметить нельзя, а группа, где все копии лежат внутри пакетов, не показывается.
- Участник, у которого после поиска изменились размер, время изменения или файл на его месте, выбывает из группы.
- Копия, которая делит блоки с оставляемым экземпляром (клон APFS или жёсткая ссылка), помечается «клон APFS» и не отмечается: её удаление не освобождает место. Копии, которые делят блоки только между собой, отмечаются как обычные; их общие блоки в «освободит» не засчитываются.
- Копия удаляется только рядом со своим оставляемым экземпляром: перед удалением она побайтово сверяется с ним. Если копия уже отличается, оставляемый экземпляр пропал или тоже отмечен к удалению, копия остаётся, а причина видна в «Не удалено».
- Действие над копией — открытое решение (раздел 3).

### 4.6 AI-слой

**Процессы.** Основное приложение держит агентный цикл, индекс и загрузчик. XPC-сервис `DomovoiInference.xpc` держит llama.cpp и веса модели (через mmap). launchd поднимает сервис по первому запросу. Падение инференса не роняет интерфейс.

**Протокол XPC (libxpc).** Сообщения:

- загрузить и выгрузить модель;
- запрос генерации: промпт, грамматика, параметры сэмплинга;
- стрим токенов обратно;
- отмена.

**Грамматика.** Модель отвечает строго одним из двух объектов: вызов инструмента с аргументами или финальный ответ. Это обеспечивает формат на любой модели, независимо от нативной поддержки tool calling.

**Инструменты агента** (только чтение индекса):

- `query_index` — выборка узлов по фильтрам (категория, безопасность, размер, давность, префикс пути);
- `inspect_node` — метаданные одного узла и его крупнейших детей;
- `rule_explain` — пояснение правила по id;
- `summarize` — агрегаты по категориям и уровням безопасности.

Модель не вызывает действий над файлами. Кнопки вида «Отметить к удалению» в ответе формирует приложение по результатам инструментов, а не по тексту модели. Модель может назвать, что предлагает отметить: локальная — полем `targets` финального ответа (до 5 путей), Claude Code — инструментом MCP `mark_for_deletion`, который сразу отвечает ошибкой на путь вне индекса или без разрешающего правила. Названное важнее выведенного: если цели есть, кнопки строятся только из них, иначе — из узлов, которые вернули инструменты. Для обоих источников проверка одна — правило на пути или его предке, уровень не «проверьте сами», правило не справочное, denylist молчит, — поэтому «отметь только v3» в хранилище pnpm даёт кнопку на `v3`, а уровень и запреты по-прежнему решают правила.

Кнопка «Спросить Домового» на карточке рекомендаций открывает раздел «Домовой» и задаёт фиксированный вопрос о карточке. Сама карточка (правило, заголовок, уровень, первые 10 путей с их общим числом, размер) идёт в сводку вопроса полем `card` как недоверенные данные, а не в текст вопроса: заголовок гипотезы — имя папки. У карточки «Проекты разработки» правила нет, её пути — артефакты проектов по убыванию размера. Локальная модель на первом шаге обязана вызвать инструмент; Claude Code получает ту же сводку и ведётся инструкцией. Уровень карточки ответ не меняет. Пока ассистент отвечает, кнопка недоступна; если ассистент выключен или модели нет, кнопка только открывает «Домовой» с объяснением.

**Контекст.** Дерево целиком модели не передаётся, только агрегаты и результаты инструментов.

**Задачи модели:**

- классификация неизвестных папок, с пометкой «гипотеза модели» (например, остаток удалённого приложения);
- ответы на вопросы о диске на естественном языке;
- сводка: сколько можно освободить и почему.

**Выгрузка** из памяти после простоя, по таймауту из настроек.

### 4.7 Загрузчик и каталог моделей

- **Запись каталога:** имя, класс (компактная / стандартная / расширенная), URL, размер, SHA-256, минимальный объём общей памяти, семейство и шаблон промпта, лицензия весов.
- **Модель по умолчанию** выбирается по объёму общей памяти Mac.
- **Загрузка:** HTTP Range с докачкой, пауза, отмена, предварительная проверка свободного места, проверка SHA-256 после загрузки.
- **Хранение:** `~/Library/Application Support/Domovoi/models`.
- **Источник загрузки** настраивается. Файл, положенный вручную, принимается, если совпадает хэш.
- **Отображение.** Модель видна на диаграмме в категории «Модель» и удаляется из настроек.

### 4.8 Интерфейс

AppKit через objc2. Разделы в сайдбаре: Macintosh HD, Рекомендации, Дубликаты, Домовой (AI), Модель (настройки).

Экраны (книга, раздел VII):

1. Первый запуск: доступ к диску; иконка для перетаскивания в список Full Disk Access.
2. Сканирование.
3. Главное окно: диаграмма, крошки, список уровня.
4. Рекомендации: итог по уровням безопасности, карточки правил, карточка «Проекты разработки» со строкой на проект и гипотезы модели; на каждой карточке — «Спросить Домового». Заранее ничего не отмечено: карточку, проект или группу проектов отмечают сами, и пока отметок нет, кнопка «Отметить к удалению» неактивна. Отметки переживают прокрутку и обновление экрана после изменений на диске.
5. Домовой: чат с видимыми вызовами инструментов.
6. Дубликаты. Заранее ничего не отмечено: копии отмечают сами, и пока отметок нет, кнопка «Отметить к удалению» неактивна. Заголовок и значок в сайдбаре показывают, сколько можно освободить; кнопка — сколько освободят отмеченные копии.
7. Модель: каталог, загрузка, таймаут выгрузки, источник.
8. К удалению: подтверждение перед удалением. После подтверждения список запущенных программ проверяется заново: бандл программы, запущенной уже после открытия Домового, и файлы правила, чья программа-владелец сейчас работает (например, диск Docker при запущенном Docker), не удаляются, причина видна в «Не удалено». Если проверить запущенные программы не удалось, удаление не начинается. Программа, удаляемая вместе с файлами, — одна группа «<имя> и его файлы» с путями и причинами; папки, совпавшие только по имени, видны отдельно как неотмеченные. У каждой строки до начала удаления — крестик «Снять отметку». Лист не выше окна: длинный список строк (и список «Не удалено» в итоге) прокручивается, а итог и кнопки остаются на месте; обновление листа во время замера и удаления не сбрасывает прокрутку.

Узел на главном экране: контекстное меню строки уровня и крошки — «Показать в Finder», «Открыть в Terminal» (каталог узла или родитель файла, через `NSWorkspace`) и «Свойства» (собственная панель: имя, размер, путь, источник, даты создания и изменения, число файлов внутри, владелец с признаком, например «Владелец: Slack · метаданные контейнера»). У бандла программы в меню строки и в свойствах есть «Удалить вместе с файлами»: в «К удалению» уходят бандл и всё, чем программа владеет по точным признакам. Вложенная папка с именем родителя подписывается «Music ▸ Music» в списке уровня, наведении и центре солнца; крошки не меняются. «Файл ▸ Экспортировать список…» пишет весь индекс в CSV (`path,bytes,category,modified`, RFC 4180, байты числом, дата в UTC) через `NSSavePanel`. Пробел в списке уровня и в списке дубликатов открывает Quick Look (`QLPreviewPanel`) для выделенных строк; строки списка «К удалению» выделения не имеют, их предпросмотр доступен из списка уровня. Строки списка уровня — одна или несколько выделенных — перетаскиваются на кнопку «К удалению» в шапке; тянутся только узлы скана, а «Скрытое», «Другие тома» и сборная строка мелких — нет. Перетаскивание идёт только внутри Домового: в Finder и другие программы строку не бросить. Пока строку тащат, кнопка обведена; над ней она говорит, что будет: «Добавить 2 объекта · ≈ 36,0 ГБ», «Добавить 1 из 2 · ≈ …», если часть отсеяна, «Нельзя: системный том» — причина denylist, или «Уже в списке», если папка сама или её родитель уже отмечены. После броска с отказами под кнопкой на 4 с остаётся строка «Не добавлено: <имя> — <причина>». С непустым списком кнопка показывает число отметок и оценку объёма: «К удалению · 3 · ≈ 42,2 ГБ»; точный объём считает лист. Во время скана иконка в Dock несёт полосу прогресса (`NSDockTile`), а если окно не активно, по окончании приходит уведомление «Скан завершён за N» (`UNUserNotificationCenter`, разрешение запрашивается при первом скане из бандла); вне бандла и плитка, и уведомление молчат. Контекстное меню строки «Скрытое» или «Purgeable» при непустом списке снапшотов предлагает «Скопировать команду tmutil»: в буфер обмена (`NSPasteboard`) ложится текст из строк `tmutil deletelocalsnapshots <дата>` по каждому снапшоту Time Machine и одной `tmutil thinlocalsnapshots / 10000000000 4`, если есть снапшоты других классов; сам Домовой `tmutil` не запускает. Та же строка при ненулевой оценке purgeable и найденных функциях CoreServices предлагает «Освободить…»: пункт открывает лист «Освобождение» на главном окне, как список «К удалению» перед удалением. Три состояния в одном листе: подтверждение — «Можно освободить до X» и что уходит (локальные бэкапы Time Machine, если они объясняют purgeable, загруженные копии файлов iCloud, системные кэши; порядок выбирает macOS), кнопка «Освободить» помечена разрушительной, «Отмена» по Escape; работа — «Освобождаю: X из Y», полоса по росту свободного места и кнопка «Остановить»; итог — «Освобождено: X» и одна строка причины, если работа кончилась не сама (остановлена, вышло время, рост прекратился), ошибка механизма — тоже итог. Пока лист открыт, пункт не предлагается и перескан ждёт; после итога обзор диска перемеряется и экран обновляется, как после удаления.

Отмеченное видно и в главном окне. Строка уровня, чья папка лежит в «К удалению» или внутри отмеченной папки, гаснет — имя, размер, точка и полоса уходят в приглушённый цвет — и несёт слева от размера метку «к удалению»; имя обрезается первым, метка и размер — никогда, VoiceOver читает «<имя>, к удалению». Диаграмма показывает диск таким, каким он станет после удаления: сегмент отмеченной папки вместе с её кольцами за 320 мс сжимается к центру, соседи по уровню забирают его угол, порядок сегментов не меняется; снятие отметки возвращает сегмент тем же движением. Центр по-прежнему называет нынешний размер уровня — байты ещё на диске, освобождаемое показывает кнопка «К удалению». Внутри отмеченной папки сжатия нет: все строки её уровня несут метку, а кольцо остаётся целым. Отмеченный путь глубже раскрытой части диаграммы (она строится от фокуса с бюджетом узлов) не даёт ни метки, ни сжатия: его байты вычитаются из ближайшей показанной папки и её предков. Treemap геометрию не анимирует — плитки перестраиваются сменой кадра, как при зуме. Отметка выводится заново из списка при каждой его смене и при каждой перестройке экрана.

Компоненты AppKit по экранам и правила обрезки текста — в книге, раздел X. Коротко:

- размеры и счётчики никогда не обрезаются;
- пути обрезаются в середине;
- имена обрезаются в конце, полный текст в подсказке и VoiceOver;
- многострочный текст переносится;
- длинные окна прокручиваются, шапка с итогом закреплена.

## 6. Итоги практических проверок

1. **Клоны APFS.** `getattrlistbulk` отдаёт `ATTR_CMNEXT_CLONEID`, `ATTR_CMNEXT_CLONE_REFCNT`, `ATTR_CMNEXT_EXT_FLAGS` (`EF_SHARES_ALL_BLOCKS`, `EF_MAY_SHARE_BLOCKS`) и `ATTR_CMNEXT_PRIVATESIZE`; на macOS 15+ всё доступно. `EF_MAY_SHARE_BLOCKS` — липкий признак «когда-либо клонировался», а не факт разделения. У сжатых файлов `CLONE_REFCNT` и `PRIVATESIZE` равны 0 даже без клонов. `PRIVATESIZE` удорожает обход в 1,8–2,6 раза и меняется снапшотами, поэтому в обходе не запрашивается.
2. **`kMDItemLastUsedDate`.** Для файлов дата лежит в xattr `com.apple.lastuseddate#PS`, для каталогов и бандлов — только в индексе Spotlight (один запрос `MDQuery` после скана). Поштучный `MDItemCopyAttribute` подставляет mtime и не используется. Копии наследуют дату. `atime` не сигнал.
3. **Full Disk Access.** Публичного API нет; проба — реальный `opendir` защищённого пути: EPERM при успешном `stat` — нет доступа, EACCES — права, EPERM уже на `stat` — Data Vault. Первая проба сама добавляет приложение в список; выданное право видно после перезапуска.
4. **Firmlinks и Data-том.** Корень обхода — Data-том (`MNT_EXT_ROOT_DATA_VOL`), обход по `dirfd`; смена тома видна только по `ATTR_DIR_MOUNTSTATUS`; системный том — один сегмент «macOS» по `ATTR_VOL_SPACEUSED`.
5. **Purgeable и снапшоты.** Занятое томом — только `ATTR_VOL_SPACEUSED`; purgeable — оценка `Important − Available` из `NSURLVolumeAvailableCapacityForImportantUsageKey`; снапшоты перечисляются `fs_snapshot_list` без root, но их размер публично недоступен. Остаток скрытого места после purgeable показывается как «Не удалось найти»: служебные данные APFS и закрытые папки; домашние папки других пользователей (`EACCES` на листинге `/Users/*`) считаются числом, их размер без прав администратора не измерить. Purgeable объясняется локальными бэкапами Time Machine, если в `/Library/Preferences/com.apple.TimeMachine.plist` включён `AutoBackup` или `MobileBackups` (отсутствие ключа или файла — настройка неизвестна). Освобождение purgeable идёт через закрытые функции CoreServices `CSDiskSpaceGetRecoveryEstimate`, `CSDiskSpaceStartRecovery` и `CSDiskSpaceCancelRecovery` (механизм CacheDelete), найденные через `dlsym` и вызываемые на корне Data-тома; нет функций — нет пункта меню. Освобождённое считается по росту `ATTR_VOL_SPACEAVAIL`, а не по изменению `Important`: та оценка уже включает место про запас и после освобождения почти не меняется. Запуск завершается по обратному вызову механизма; если после достижения оценки рост стоит 5 с — итог «рост прекратился», через 120 с посылается отмена и итог считается по измеренному. Вызовы механизма идут только в потоке задачи, главный поток опрашивает её таймером; `tmutil` Домовой по-прежнему не запускает.
6. **Tool use под грамматикой.** Грамматика не ухудшает выбор инструмента, если схема и пример видны в промпте; совмещение вызова и схемы ответа в одном проходе может подавлять вызовы, поэтому эвал меряет долю вызовов при явной необходимости.
7. **Текст на не-Retina.** SDF ниже ~18 px нечитаем; текст диаграммы — растровый атлас на точный размер (см. 4.3).
