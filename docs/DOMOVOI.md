# DOMOVOI

Анализатор диска для macOS в духе DaisyDisk: показывает, где лежит занятое место, рекомендует, что можно убрать, и отвечает на вопросы о диске с помощью локальной языковой модели. Написан на Rust, диаграмма рисуется в Metal.

Имя: Домовой — хранитель дома из славянской мифологии, который знает каждый угол и держит порядок, но ничего не делает без спроса.

Визуальная спецификация: `design/domovoi-design-book.html` (дизайн-книга, разделы I–XI). Этот документ описывает продукт и архитектуру. Книга описывает внешний вид, компоненты, экраны и правила рендера. При расхождении в визуальных вопросах права книга, в остальных — этот документ.

---

## 1. Принципы

1. **Честные числа.** Показываем только измеренное: размер на диске (allocated), а не логический. Hard links считаются один раз. Клоны APFS помечены. Скрытое место (purgeable, снапшоты, системные данные) показано отдельно и не смешивается с файлами.
2. **Правила решают, модель объясняет.** Безопасность удаления определяет только детерминированный движок правил. Модель классифицирует незнакомое и отвечает на вопросы. Её выводы всегда помечены как гипотеза и попадают в категорию «Проверьте сами».
3. **Ничего без спроса.** Удаление только в Корзину Finder и только после подтверждения. Системные пути, SIP-защищённые области и активные бандлы приложений закрыты denylist.
4. **Ничего наружу.** Модель видит только метаданные. Процесс инференса не имеет доступа к сети.
5. **Приложение работает без модели.** Скан, диаграмма, правила, дубликаты и очистка доступны сразу. AI включается отдельно.
6. **Модель тоже занимает место.** Скачанная модель видна на диаграмме отдельной категорией и удаляется в один клик.

## 2. Принятые решения

| # | Область | Решение |
|---|---|---|
| 1 | Объём сканирования | Только системный том. Другие тома, внешние и сетевые диски не сканируются. |
| 2 | Сканер | `getattrlistbulk`, параллельный обход по поддеревьям, allocated size, дедупликация hard links по `(dev, inode)`, кэш скана на диске, инкрементальные обновления через FSEvents. |
| 3 | Дубликаты | Отдельная опция и отдельный проход: группировка по размеру → частичный хэш → полный BLAKE3. Клоны APFS распознаются. |
| 4 | Рекомендации | Детерминированный движок правил с уровнями безопасности. Модель не принимает решений об удалении. |
| 5 | Удаление | Только `NSFileManager trashItem`, никогда `unlink`. Перед действием всё собирается в «Корзину Домового». |
| 6 | Данные для модели | Только метаданные: путь, имя, размер, тип/UTI, даты создания и изменения, `kMDItemLastUsedDate`, принадлежность приложению. Содержимое файлов не читается. `kMDItemWhereFroms` исключён. |
| 7 | Рантайм модели | llama.cpp, статически слинкованный, на запиненном коммите. Metal-бэкенд, metallib встроена (`GGML_METAL_EMBED_LIBRARY`). |
| 8 | Биндинги | Свои, тонкий слой через bindgen над `llama.h`. Готовые крейты не используются. |
| 9 | Изоляция инференса | XPC-сервис внутри бандла (`Contents/XPCServices`), протокол через C API `libxpc`. У сервиса нет сети. |
| 10 | Формат ответов модели | Structured output и tool calling через грамматику GBNF, построенную из JSON-схемы. Модель физически не может ответить вне схемы. |
| 11 | Шаблоны промптов | Свои для каждого семейства моделей, хранятся в каталоге. Встроенные шаблоны llama.cpp не используются. |
| 12 | Выгрузка модели | После простоя. Таймаут выбирает пользователь: сразу, 5, 15, 60 минут, никогда. |
| 13 | Загрузка модели | Внутри приложения, своим загрузчиком: HTTP Range (докачка), пауза, отмена, проверка SHA-256, проверка свободного места. Бинарник приложения моделей не содержит. |
| 14 | Каталог моделей | Зашит в версию приложения. Новые модели приходят с релизами. Источник загрузки настраивается (зеркало или файл вручную), подлинность проверяется по SHA-256. |
| 15 | Интерфейс | AppKit через objc2: окно, сайдбар, списки, карточки, чат, настройки. Metal только для диаграммы. |
| 16 | Дистрибуция | Вне Mac App Store: Developer ID, notarization, обновления через Sparkle. |
| 17 | Единицы | Десятичные, как в Finder: 1 ГБ = 10⁹ байт. Десятичная запятая, неразрывный пробел перед единицей. |

## 3. Открытые решения

1. **Визуализация:** sunburst, treemap или оба режима с переключателем. Сравнение на одних данных — в разделе V дизайн-книги.
2. **Действие над дубликатом:** удаление копий в Корзину, замена копий клонами APFS через `clonefile` или выбор пользователя.
3. **Состав каталога моделей:** конкретные модели для 8, 16 и 32+ ГБ общей памяти. Критерии: качество tool use под грамматикой на маленьких моделях, поддержка русского языка, лицензия весов, допускающая распространение через каталог.

## 4. Подсистемы

### 4.1 Сканер

- Обход через `getattrlistbulk`: имена, тип, allocated size, inode, даты пачкой за один syscall.
- Параллельность по поддеревьям, work-stealing.
- Data-том системного контейнера; firmlinks между `/` и `/System/Volumes/Data` учитываются, чтобы ничего не посчитать дважды.
- Примонтированные тома и точки монтирования внутри дерева пропускаются.
- Hard links считаются один раз по `(dev, inode)`.
- Sparse-файлы считаются по allocated size.
- Клоны APFS: блоки делятся, честно посчитать нельзя. Клоны помечаются, где их удаётся распознать (clone id и флаг возможного разделения блоков через `getattrlist`; доступность и поведение API нужно проверить на практике).
- Скрытое место считается отдельно, без обхода файлов: purgeable, локальные снапшоты Time Machine, системные данные.
- **Full Disk Access.** Без него TCC закрывает `~/Library`, Mail, Safari и данные приложений. Приложение определяет отсутствие доступа, показывает экран онбординга и ведёт в Настройки. Без доступа скан работает, но показывает, сколько папок скрыто.
- **Кэш.** Результат скана сохраняется на диск. Повторное открытие мгновенное, затем применяются дельты FSEvents.

### 4.2 Индекс

Дерево узлов в памяти. Узел хранит: имя, тип, allocated size (своё и суммарное), число файлов, даты, `kMDItemLastUsedDate` (если доступно), категорию, признак клона, признак hard link, принадлежность приложению (bundle id, установлено ли приложение).

Категории: Приложения, Разработка, Медиа, Документы, Кэши, Система, Скрытое, Модель. Цвета категорий — в книге, раздел II.

Индекс отвечает на запросы с фильтрами (категория, безопасность правила, минимальный размер, давность последнего использования, префикс пути). Этими же запросами пользуется агентный цикл модели.

### 4.3 Визуализация

- `MTKView` в режиме по запросу: кадр рисуется только при изменении данных, наведении или анимации. Во время анимаций — до 120 Гц на ProMotion.
- Сегменты — инстансы: SDF-дуга (sunburst) или прямоугольник (treemap), один draw call.
- Hit-testing на CPU: полярные координаты для sunburst, дерево прямоугольников для treemap.
- Анимации: радиальный зум 220 мс, приглушение остальных сегментов при наведении 120 мс, сжатие сегмента при перемещении в корзину 320 мс. Сектор роста во время скана отражает фактический прогресс обхода. При `prefers-reduced-motion` переходы заменяются сменой кадра.
- Текст: растеризация глифов через Core Text в SDF-атлас (с кириллицей), раскладка и обрезка строк через `CTLine` / `CTLineCreateTruncatedLine`.
- Текст в центре круга подгоняется по хорде на высоте строки: сначала уменьшение до минимального размера, затем многоточие.
- Подписи treemap рисуются только в плитках больше порога, иначе имя доступно по наведению.

### 4.4 Движок правил

Правило: идентификатор, набор путей или шаблонов, уровень безопасности, пояснение для пользователя.

Уровни безопасности:

- **Безопасно** — пересоздаётся само.
- **Восстановимо** — можно скачать заново, но что-то пропадёт.
- **Проверьте сами** — могут быть данные пользователя.

Стартовый набор правил:

| id | Что | Уровень |
|---|---|---|
| `xcode.derived-data` | Xcode DerivedData | Безопасно |
| `xcode.device-support` | iOS DeviceSupport | Безопасно |
| `cargo.target` | каталоги `target/` Rust-проектов | Безопасно |
| `dev.deps` | `node_modules`, `zig-cache` и подобные | Безопасно |
| `caches.user` | `~/Library/Caches` | Безопасно |
| `downloads.installers` | `.dmg` и `.pkg` в Загрузках | Безопасно |
| `xcode.simulators` | симуляторы CoreSimulator | Восстановимо |
| `docker.vm` | диск виртуальной машины Docker | Проверьте сами |
| `ios.backups` | резервные копии iPhone и iPad | Проверьте сами |
| `xcode.archives` | архивы Xcode | Проверьте сами |

Правила для кэшей пакетных менеджеров (Homebrew, npm, cargo, pip, Yarn, SwiftPM) входят в `caches.user` или выделяются отдельно — решает планирование.

- **Denylist** закрывает системные пути, SIP-защищённые области и бандлы запущенных приложений. Ни правило, ни пользователь не могут переместить их в корзину.
- **Корзина Домового** — промежуточный список выбранного перед действием. Показывает итог и перемещает всё в Корзину Finder одной операцией.

### 4.5 Дубликаты

- Запускается вручную, отдельным проходом с прогрессом и отменой.
- Конвейер: группировка по размеру → хэш первых и последних блоков → полный BLAKE3 только для оставшихся кандидатов.
- Клоны APFS внутри группы помечаются: их удаление почти не освобождает место.
- Действие над копией — открытое решение (раздел 3).

### 4.6 AI-слой

**Процессы.** Основное приложение держит агентный цикл, индекс и загрузчик. XPC-сервис `DomovoiInference.xpc` держит llama.cpp и веса модели (через mmap). launchd поднимает сервис по первому запросу. Падение инференса не роняет интерфейс.

**Протокол XPC (libxpc).** Сообщения:

- загрузить и выгрузить модель;
- запрос генерации: промпт, грамматика, параметры сэмплинга;
- стрим токенов обратно;
- отмена.

**Грамматика.** Модель отвечает строго одним из двух объектов: вызов инструмента с аргументами или финальный ответ. Это обеспечивает формат на любой модели, независимо от нативной поддержки tool calling.

**Инструменты агента** (только чтение индекса):

- `query_index` — выборка узлов по фильтрам (категория, безопасность, размер, давность, префикс пути);
- `inspect_node` — метаданные одного узла и его крупнейших детей;
- `rule_explain` — пояснение правила по id;
- `summarize` — агрегаты по категориям и уровням безопасности.

Модель не вызывает действий над файлами. Кнопки вида «Добавить в Корзину Домового» в ответе формирует приложение по результатам инструментов, а не по тексту модели.

**Контекст.** Дерево целиком модели не передаётся, только агрегаты и результаты инструментов.

**Задачи модели:**

- классификация неизвестных папок, с пометкой «гипотеза модели» (например, остаток удалённого приложения);
- ответы на вопросы о диске на естественном языке;
- сводка: сколько можно освободить и почему.

**Выгрузка** из памяти после простоя, по таймауту из настроек.

### 4.7 Загрузчик и каталог моделей

- **Запись каталога:** имя, класс (компактная / стандартная / расширенная), URL, размер, SHA-256, минимальный объём общей памяти, семейство и шаблон промпта, лицензия весов.
- **Модель по умолчанию** выбирается по объёму общей памяти Mac.
- **Загрузка:** HTTP Range с докачкой, пауза, отмена, предварительная проверка свободного места, проверка SHA-256 после загрузки.
- **Хранение:** `~/Library/Application Support/Domovoi/models`.
- **Источник загрузки** настраивается. Файл, положенный вручную, принимается, если совпадает хэш.
- **Отображение.** Модель видна на диаграмме в категории «Модель» и удаляется из настроек.

### 4.8 Интерфейс

AppKit через objc2. Разделы в сайдбаре: Macintosh HD, Рекомендации, Дубликаты, Домовой (AI), Модель (настройки).

Экраны (книга, раздел VII):

1. Первый запуск: доступ к диску.
2. Сканирование.
3. Главное окно: диаграмма, крошки, список уровня.
4. Рекомендации: итог по уровням безопасности, карточки правил и гипотез модели.
5. Домовой: чат с видимыми вызовами инструментов.
6. Дубликаты.
7. Модель: каталог, загрузка, таймаут выгрузки, источник.
8. Корзина Домового: подтверждение перед перемещением в Корзину.

Компоненты AppKit по экранам и правила обрезки текста — в книге, раздел X. Коротко:

- размеры и счётчики никогда не обрезаются;
- пути обрезаются в середине;
- имена обрезаются в конце, полный текст в подсказке и VoiceOver;
- многострочный текст переносится;
- длинные окна прокручиваются, шапка с итогом закреплена.

### 4.9 Дистрибуция

- Developer ID и notarization.
- Обновления через Sparkle.
- Entitlements для hardened runtime.
- XPC-сервис подписан вместе с бандлом.
- Mac App Store не поддерживается: песочница несовместима со сканированием всего тома.

## 5. Голос интерфейса

Спокойно и по делу, как мастер, который знает дом. Вещи называются так, как их видит человек в Finder. Без восклицаний, шуток про мусор и фраз вроде «ваш Mac теперь летает». Гипотезы формулируются как гипотезы: «Похоже на…». Таблица формулировок — в книге, раздел VIII.

## 6. Что проверить на практике

1. API распознавания клонов APFS: поля `getattrlist`, их доступность на текущих версиях macOS.
2. Надёжность `kMDItemLastUsedDate` для каталогов и файлов без индексации Spotlight. `atime` на APFS как сигнал не используется.
3. Определение отсутствия Full Disk Access без побочных эффектов.
4. Корректный обход firmlinks и Data-тома без двойного счёта.
5. Получение purgeable-места и размера локальных снапшотов без привилегий.
6. Качество tool use под грамматикой на моделях класса 3–4B.
7. SDF-атлас с кириллицей и качество мелкого текста на не-Retina дисплеях.
