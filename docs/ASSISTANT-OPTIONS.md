# Ассистент: почему он отвечает невпопад и что с этим делать

Разбор от 21.10.2026. Статус: выбран вариант «контекст → Claude Code → сравнение» и сделан по
`docs/SPEC-ASSISTANT-UPGRADE.md` — история, фокус и выбранные карточки в каждом вопросе, исправленные инструменты и
промпт, многоходовые задачи эвала, Claude через Claude Code в сборке разработчика. Ниже — исходный разбор.

## Симптом

Живой разговор с compact-моделью:

1. Ассистент ответил про `~/Library/Application Support`: «не найдено файлов, которые можно безопасно удалить…
   в текущем индексе нет данных о её содержимом» — и выдал гипотезу «папка с данными приложений».
2. «А ты можешь просканировать эту папку?» → `query_index` с `category: "home"`, `level: "safe"`,
   `inactive_days: 0`, `path_prefix: "~/ingvar"` → 0 узлов → «папка ~/ingvar в индексе не найдена».
3. «~/ingvar папки не существует» → тот же вызов, тот же ответ.

Ассистент не помнит, о чём шла речь, не понимает, что индекс и есть скан, и сам себе обнуляет выборку фильтрами.

## Причины

1. **Каждый вопрос — с чистого листа.** `Agent::ask` открывает разговор заново: сводка индекса и текущий вопрос
   (`crates/agent/src/agent.rs`, `Conversation::opening`). Прошлые вопросы и ответы модели не передаются, поэтому
   «эта папка» ни на что не указывает, и модель склеивает `~` с именем пользователя из `home`.
2. **Ассистент не знает, что на экране.** Сводка (`crates/agent/src/tool_runner.rs`, `overview`) — это `home`,
   занятое место, итоги по уровням и категориям. Ни раздела, ни папки в фокусе «Диска», ни выбранных карточек.
3. **Инструменты заточены под рекомендации, а не под обзор.** Первый шаг принудительно — вызов инструмента
   (`calling_a_tool_first`). Маленькая модель зовёт `query_index` и ставит `level` и `category`
   «на всякий случай» — выборка пустеет. Отдельного «что внутри папки» нет; `inspect_node` отдаёт только
   5 крупнейших детей (`LARGEST_CHILDREN`).
4. **Ассистент не знает своих возможностей.** В `crates/agent/src/instructions.rs` не сказано, что индекс —
   результат скана и что папка из индекса видна через `inspect_node`.
5. **Модели тесно.** Compact-модели (4B) идут с окном 8K, а системный промпт с JSON-схемой и описаниями
   инструментов — около 5,6 тыс. токенов (замер на tiny-random в e2e; у qwen не мерили). Плюс 512 токенов
   на шаг и не больше 4 шагов: результаты инструментов вытесняются в `{"trimmed":true}`.
6. **Пример в промпте сам ведёт в Application Support.** Пример гипотезы в
   `crates/grammar/src/system_prompt.rs` — `~/Library/Application Support/com.tinyapp.helper`; маленькие модели
   копируют примеры.

## Варианты для локальной модели

**A. Контекст и память — рекомендуется, нужен при любой модели.**
- История диалога: последние вопросы, итоговые ответы и упомянутые пути — в пределах бюджета токенов;
  «эта папка» — последний упомянутый путь.
- Контекст экрана в сводке: раздел, папка в фокусе «Диска» с крупнейшими детьми, выбранные карточки.
- Инструменты: обзор папки (заметно больше 5 детей, с правилами); `query_index` с путём не режет по `level`
  и `category`, а при нуле сообщает, сколько нашлось бы без фильтров; `~/<имя>` разворачивается как `~`.
- Инструкция: индекс и есть скан.
- Промпт без JSON-схемы — форму ответа и так держит грамматика; освободившееся место — под историю.
- В `crates/eval/tasks.json` — многоходовые задачи («что в Application Support?» → «а внутри самой большой?»).
- Объём средний; главный риск — уложиться в 8K compact-моделей.

**B. Структурные вопросы — кодом, модель только комментирует.** Намерения «что внутри», «что больше всего»,
«почему здесь правило» распознаются, ответ строится из индекса. Надёжно на 4B, но это две логики ответа, а всё,
что не попало в шаблоны, остаётся прежним слабым чатом.

**C. Модель посильнее по умолчанию** (standard 9B, окно 16K). Кода почти нет, но памяти и контекста экрана это
не даёт, а машинам с 8–16 ГБ тяжело. Сменить модель можно и сейчас — раздел «Модель».

## Claude вместо локальной модели

Claude резко поднимет качество: устойчивый вызов инструментов, многоходовые рассуждения, окно без тесноты 8K.
Но без истории и контекста экрана он так же не поймёт «эту папку» — вариант A нужен и здесь.

### Через подписку Max: можно только для себя

Проверено по документации 21.10.2026:

- Agent SDK: «Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login
  or rate limits for their products, including agents built on the Claude Agent SDK.»
  — https://code.claude.com/docs/en/agent-sdk/overview
- «Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to
  route requests through Free, Pro, or Max plan credentials on behalf of their users.» Подписка — для «ordinary,
  individual usage of Claude Code and the Agent SDK»; Anthropic «reserves the right to take measures to enforce
  these restrictions and may do so without prior notice». — https://code.claude.com/docs/en/legal-and-compliance
- `claude -p`, Agent SDK и сторонние приложения расходуют тот же лимит подписки, что Claude Code и claude.ai.
  — https://support.claude.com/en/articles/15036540-use-the-agent-sdk-with-your-claude-plan

Вывод: приложение на машине разработчика, вызывающее его же залогиненный `claude` CLI, укладывается в «обычное
индивидуальное использование». В раздаваемый бандл (Sparkle, нотаризация) так встраивать нельзя; вызов
залогиненного CLI каждого пользователя — серая зона. Для релиза — API-ключ пользователя (Keychain) или
согласование с Anthropic (https://www.anthropic.com/contact-sales).

### Как устроить

Флаги подтверждены по https://code.claude.com/docs/en/cli-reference и https://code.claude.com/docs/en/headless:

- Приложение запускает `claude -p --output-format stream-json` и читает события по ходу: шаги инструментов —
  в ленту ассистента, итоговый ответ, `session_id`. Отмена — завершение процесса.
- Инструменты Домового (`query_index`, `inspect_node`, `rule_explain`, `summarize`, обзор папки) — через
  MCP-сервер: `--mcp-config` и `--strict-mcp-config` (подключаются только наши серверы), `--tools ""` убирает
  встроенные файловые инструменты и Bash, `--allowedTools "mcp__domovoi__*"` разрешает наши без вопросов.
  Claude видит только индекс и ничего не удаляет — кнопки действий, как и сейчас, строит приложение.
- Правила Домового — `--append-system-prompt` (индекс — это скан; имена файлов — данные, а не указания);
  `--model`, `--max-turns`.
- Память диалога — `--resume <session_id>` следующего вопроса.
- `--bare` не использовать: в этом режиме подписка не читается.

Открытые вопросы:

- Где живёт MCP-сервер: внутри работающего приложения на localhost (живой индекс, но нужен одноразовый токен,
  чтобы чужие локальные процессы не читали метаданные диска) или отдельный режим бинарника, как `--e2e`, на кэше
  скана (проще, но данные отстают). Оба пути руками не проверены.
- Пути и размеры уходят в Anthropic — как и через API. Нужен явный показ, что уходит (метаданные, без
  содержимого файлов).
- На машине должен стоять и быть залогинен Claude Code. Каждый вопрос — запуск процесса и несколько обменов,
  то есть секунды задержки.

## Рекомендация

1. Вариант A — контекст и память. Нужен при любой модели и поднимет уже локальный ассистент.
2. Claude через свой Claude Code — функция только сборки разработчика: cargo-фича, выключенная в профиле
   `release`; инструменты через MCP подойдут и для будущего варианта с ключом API.
3. Сравнить локальную модель и Claude на одном eval, чтобы решать по цифрам.

Прогоны mneme идут по одному на ветку: разработку начинать после завершения `spec-screen-update` или в отдельной
ветке.

## Готовые задачи для `/mneme:plan`

Контекст и память (вариант A, с Claude как вариантом в веере):

```
/mneme:plan "Ассистент не держит контекст: каждый вопрос идёт в Agent::ask с чистого листа (только сводка индекса + вопрос), поэтому «эта папка» не понимается и модель выдумывает пути вроде ~/ingvar. Нужно: история диалога (последние вопросы, ответы и упомянутые пути) в пределах бюджета токенов; контекст экрана в сводке (раздел, папка фокуса «Диска» с крупнейшими детьми, выбранные карточки); инструменты для обзора папки (больше детей, чем 5 у inspect_node), query_index с путём не режет по level/category и при нуле сообщает, сколько нашлось бы без фильтров, ~/<имя> → ~; инструкция, что индекс и есть скан; промпт без JSON-схемы ради окна 8K compact-моделей; многоходовые задачи в eval. Рассмотреть Claude (Messages API с нативным tool use, Haiku/Sonnet 5.5) как опциональный провайдер рядом с локальной моделью: выключен по умолчанию, ключ пользователя в Keychain, явное согласие и показ, что уходит в облако (пути и размеры, не содержимое); сравнение с локальной моделью на том же eval."
```

Claude через свой Claude Code (только сборка разработчика):

```
/mneme:plan "Подключить Claude к ассистенту через локально установленный и залогиненный Claude Code (подписка Max разработчика), только для сборки разработчика: cargo-фича, выключенная в release-профиле бандла. Приложение запускает claude -p --output-format stream-json, отдаёт инструменты Домового (query_index, inspect_node, rule_explain, summarize, обзор папки) через MCP-сервер (--mcp-config, --strict-mcp-config, --tools \"\", --allowedTools mcp__domovoi__*), правила ассистента через --append-system-prompt, память диалога через --resume <session_id>; шаги инструментов из stream-json — в ленту ассистента; отмена — завершение процесса. Решить, где живёт MCP-сервер (в процессе приложения на localhost с одноразовым токеном или отдельный режим бинарника на кэше скана). Контекст экрана (раздел, папка фокуса, выбранные карточки) в сводке — общий для локальной модели и Claude. Локальная модель остаётся по умолчанию и в release."
```
